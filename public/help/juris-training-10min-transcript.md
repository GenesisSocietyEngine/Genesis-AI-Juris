## 00:00 — A case from file to decision

Mode: Actual opening application screenshot

Welcome to Genesis: Juris Studio. In ten minutes, we will follow a canonical case from import to review and reporting, then start a new case. This is a narrated, illustrated walkthrough. The opening screen shows the application; clearly labeled instruction segments explain account features that were not recorded. Use fictional or de-identified material when you practise.

## 00:30 — Demo, Templates and your own work

Mode: Illustrated workflow — not an application screenshot

Choose Demo when you want to learn from a completed example such as Project Canopy. Its Practice cases link opens the simulation catalogue. Choose Templates when you want a starting structure for your own case. A template opens a new draft with an intake prompt; you must supply and review its facts. Neither action creates an approved organization record.

## 01:00 — Choose the complete Markdown file

Mode: Illustrated workflow — not an application screenshot

Our example is Five Flats, Three Borders, sometimes called Five Flats, Three Countries. Use the complete final Markdown file, including its embedded case data. From the entry screen, choose Import case or prompt. Inside the editor, the equivalent route is More actions, then Import case prompt, dot m d. Importing text is not yet applying its graph.

## 01:30 — Verify the exact case

Mode: Illustrated workflow — not an application screenshot

Choose Verify canonical case. This path checks the embedded structure and fingerprint locally, without asking AI to reinterpret the file. Review the verified title, version, twenty-three nodes and thirty-six relations. A matching fingerprint confirms which case data you have. It does not independently verify the evidence, legal conclusions, tax rates or any claimed review date.

## 02:00 — Apply, then review the six steps

Mode: Illustrated workflow — not an application screenshot

When the verified preview matches your intended file, choose Apply exact case. Studio reconstructs that graph and opens the working draft. Follow the six steps: Brief, Draft review, Facts and evidence, Decision map, Test, and Finish. The progress indicator describes filled sections. It does not mean every assumption is proven or that the draft has been saved.

## 02:30 — Read the mandate before editing

Mode: Illustrated workflow — not an application screenshot

Read the title, jurisdiction, professional role and Case context. This fictional matter concerns a PRC-resident client, five English flats and a proposed Liechtenstein structure. The client's preferred structure is a request to investigate, not the answer. Keep alternative routes, unresolved questions and stop conditions visible. Preserve the original file before changing its reviewed working copy.

## 03:00 — Trace evidence to the decision

Mode: Illustrated workflow — not an application screenshot

Inspect the evidence and the decision it supports. For example, the KYC questionnaire connects to the ownership and funds investigation. A named evidence node is not proof that its underlying document has been accepted. Record what the source establishes, what remains uncertain, and which decision depends on it. Use case actions to return directly to missing information.

## 03:30 — Check the current financing inputs

Mode: Illustrated workflow — not an application screenshot

Review the current file's economics rather than an older demo. It specifies a one-million-pound price, eight hundred thousand pounds of debt, seven-point-five percent interest and a one-hundred-and-twenty-month amortizing term. Gross annual rent is two hundred and forty-nine thousand, six hundred pounds. Check repayment basis, operating costs and structure costs before interpreting any displayed result.

## 04:00 — Interpret outcomes without inventing certainty

Mode: Illustrated workflow — not an application screenshot

The requested ten-percent return needs a named measure. Gross yield, cash-on-cash return and equity I R R answer different questions. Compare the displayed calculations with their assumptions and source evidence. This file contains provisional acquisition costs and unverified tax-rate sources. We are demonstrating the review workflow, not confirming a tax advantage or promising that the target is achieved.

## 04:30 — Follow a route and its alternatives

Mode: Illustrated workflow — not an application screenshot

Open Decision map and select a decision. Read the node detail, then follow its connections to the next question or outcome. In this case, defining the return metric and checking lawful funding are meaningful gates. Follow a stop or renegotiation route as well as a proceeding route. A useful map explains why different evidence can change the decision.

## 05:00 — Resolve checks before sharing

Mode: Illustrated workflow — not an application screenshot

Choose Test and read the checks for this case type. A playable case needs intentional routes and outcomes; Test this case opens its simulation when ready. Other decision packages use completeness checks. If an action identifies a missing field or connection, open it and correct the draft. A successful structural test does not replace evidence review or professional judgment.

## 05:30 — Preview an analytical draft

Mode: Illustrated workflow — not an application screenshot

Choose Create analytical report. The Create case report dialog offers Preview PDF and Download PDF, with further options under Report settings and approval. Begin with an internal review draft. Inspect its case identity, assumptions, evidence register and portrait decision map. Downloading a preliminary report does not create independent approval or a governed report in My cases.

## 06:00 — Keep a portable case and check the PDF

Mode: Illustrated workflow — not an application screenshot

After choosing Download PDF, check your browser's downloads and open the file yourself. The message PDF download started confirms initiation, not delivery. To preserve an editable canonical handoff, use More actions, then Export Final case prompt, dot m d. Read its status controls carefully. A filename containing Final does not supply missing evidence or create independent reviewer approval.

## 06:30 — Save and reopen: account instructions

Mode: Account workflow instructions — completion not recorded

This account workflow is an instruction, not a recorded successful save. With supported sign-in, Save to workspace stores a Studio draft under your account. Reopen it through Open saved Studio drafts and check the restored content. Organization cases in My cases are separate. If a save is uncertain, preserve your export and investigate before repeating a potentially completed write.

## 07:00 — Start a clean working draft

Mode: Illustrated workflow — not an application screenshot

Now create your own fictional case. Preserve the current work first, return to Case Studio and choose Create a case. Read any replacement or unsaved-work prompt before proceeding. The new draft starts a separate authoring task. Alternatively, choose a suitable starter in Templates; review its case type and intake questions instead of treating the starter as a finished example.

## 07:30 — Write a useful brief

Mode: Illustrated workflow — not an application screenshot

In Brief, describe who is involved, the decision required, the jurisdiction, known facts, available evidence and the deadline. For practice, ask whether a fictional business should approve a supplier change before a planned launch. Mark prices and delivery claims as unverified until supported. State the alternatives and the conditions that would make you pause rather than proceed.

## 08:00 — Optional AI: review before applying

Mode: Account workflow instructions — completion not recorded

This optional AI path is an instruction, not a recorded authenticated request. Where enabled, Understand with AI requires sign-in and a confirmed profile. It proposes changes for review before you apply them. Check the current data-handling notice before sending material. If unavailable, continue with manual editing or the explicitly labeled local fallback; do not mistake fallback output for AI analysis.

## 08:30 — Complete, connect and review

Mode: Illustrated workflow — not an application screenshot

For the new draft, complete Facts and evidence, then build or review the Decision map. Give nodes concrete titles and connect each choice to a reasoned next step. Add the missing evidence instead of writing an unsupported conclusion. Use Test to find structural gaps, then Finish to choose a report, workspace save or expert-review submission when its requirements are met.

## 09:00 — Create an organization case

Mode: Account workflow instructions — completion not recorded

Creating a shared organization record is a separate authenticated workflow, described here rather than recorded. Select the intended organization, open My cases and choose New case. Create a pilot matter asks for Title, Jurisdiction, Classification and Priority. After creation, verify the returned case before adding documents and reviews. Importing a canonical Studio file alone does not create this organization record.

## 09:30 — Repeat the workflow with your own example

Mode: Illustrated workflow — not an application screenshot

Your practice task is to import and verify the canonical file, explain one evidence-dependent decision, inspect a draft report, and start a new fictional case. Preserve the work you want to keep. Return to Help and guides for chapter links, instructions and troubleshooting. You have learned the workflow; reliable evidence, confirmed saves and appropriate review determine when a real case is ready.
