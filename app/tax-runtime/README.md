# Shared Rust tax runtime

This package executes the existing native tax JSON protocol. It is the P4 runtime
foundation; the web Studio editor and version-bound reports do not use it yet.
The current commands accept canonical native `ScenarioDefinition` data. The web
Studio source projection must be reviewed separately before editor integration.

Import one explicit host entry:

| Host | Entry | Initialization |
| --- | --- | --- |
| Browser | `browser.ts`: `loadBrowserTaxRuntime()` | Vite asset URL and fetch |
| Cloudflare RSC/SSR | `worker.ts`: `loadWorkerTaxRuntime()` | Imported precompiled `WebAssembly.Module` |
| Node report tools | `node.ts`: `loadNodeTaxRuntime()` | Filesystem bytes from the same generated asset |

Await the loader before calling `runtime.execute(encodedJson)`. It returns the
complete Rust JSON string; amounts and revisions remain decimal strings. Rust
owns request validation, calculations, incomplete-input errors and the 256 KiB
limit. Non-tax commands raise `unsupported_command`; initialization and capability
mismatches reject readiness. A failed loader stays failed until its module is
reloaded. There is no JavaScript financial fallback.

The ordinary web build verifies committed assets using Node only. It requires no
Rust or wasm-bindgen installation. `generated/` is owned by
`scripts/tax-wasm-assets.mjs`; do not edit its contents by hand.

To regenerate on Windows x64/MSVC, install repository Rust 1.95.0 with `wasm32-unknown-unknown` and
the exact wasm-bindgen CLI 0.2.128 into an ignored tool directory, then run:

```powershell
cargo install wasm-bindgen-cli --version 0.2.128 --locked --bin wasm-bindgen --root .artifacts/wasm-bindgen
$env:WASM_BINDGEN = '.artifacts/wasm-bindgen/bin/wasm-bindgen.exe'
npm run tax:generate
npm run tax:verify
```

The generator clears ambient compiler/profile overrides, remaps checkout and
Cargo-cache paths, uses locked dependencies and records source/artifact hashes.
It uses wasm-bindgen's `--remove-producers-section` option because that telemetry
can contain the unrelated Git HEAD enclosing the CLI's Cargo registry. The exact
tool versions remain recorded and checked in the owned receipt; executable WASM
sections are unchanged by this option.
It also regenerates the complete native reference corpus. The generator host is
pinned because Rust panic locations retain host path separators; CI on
`windows-2022` rebuilds and compares every generated byte. Linux web builds consume
the same portable WASM and verify its receipt with Node only. Library and wrapper support Rust 1.78; the generator CLI
requires a newer toolchain and runs on 1.95.

`build/tax-runtime-plugin.ts` emits explicit runtime entries through the real
Vinext client, RSC and SSR environments. Their manifests bind them to the web
application input digest. After `npm run build`, run:

```sh
CHROME_BIN="$(command -v google-chrome)" npm run tax:packaging
```

This executes the emitted Worker chunks in workerd and the emitted browser chunk
in Chrome under production security headers, retaining receipts, full responses
and screenshots under `.artifacts/tax-runtime/packaging/`. The browser test also
checks missing/corrupt WASM and a CSP that blocks WASM. Production adds only
`'wasm-unsafe-eval'`; ordinary JavaScript eval remains disallowed.

The corpus has 30 executions: capabilities, preparation, two legacy imports,
25 repetitions of the same successful calculation, and an incomplete-rates
error. This is transport parity, not broad financial or PDF report parity.
