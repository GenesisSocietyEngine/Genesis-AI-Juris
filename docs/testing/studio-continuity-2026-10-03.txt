Slice C: retention design and implementation
Intended outcome: switching cases cannot remove the only supported device copy without a recoverable earlier draft.
PO / UX design decision: account-scoped, browser-local, versioned archive; 10 entries, 2,000,000 UTF-8 bytes total; no expiry or silent eviction. These bounds are explicit implementation choices, not participant-validated capacity requirements. Verify them during the pilot before expanding them.
Eligible data: existing supported public local device records, plus the current eligible unsaved local draft and unapplied prompt. Inspect raw protection before normalization. Never archive private, sealed, copy-protected or workspace-authoritative cases. Unknown/corrupt/future active records block replacement and remain unchanged.
Ordering: confirm -> validate/read archive and active slots -> append immutable records at independent UUID keys -> recheck combined capacity -> remove known active slots -> mutate editor/clear undo/forms/authority/URL. Archive quota, format or read failure stops replacement before editor mutation. A failed append/capacity attempt removes only its own newly written records; failed rollback retains redundant recovery data and never evicts older work. Aggregate capacity is rechecked before editor mutation. The archive no longer rewrites a shared array, preventing stale-snapshot overwrite across tabs; interleaving and capacity-race tests pass. The existing single active-draft slot is still shared across tabs: a simultaneous device Save versus active-slot cleanup needs a dedicated browser rehearsal and serialization contract before general rollout. LocalStorage is not a multi-key database transaction.
Records have independent UUIDs, title, capture time, draft, prompt and exact original device text when present. Two copies of the same category remain distinct. Restore creates a fresh unsaved local identity, removes protection and parent authority, and does not create a workspace save receipt or professional approval. Tax sources/results must be rebound/recalculated if the restored identity changes.
Earlier device drafts is available only with a ready verified account. It supports explicit restore, recovery-data export/import, refresh and individually confirmed deletion. Full archives never evict unrelated work; the user exports/deletes an unwanted record before another retention write. A backup import validates format, size, eligibility, original account binding and protection before requesting replacement. A newer import, context change or unmount invalidates its delayed file read. Recovery creates an unsaved copy, not a server-sealed portable case. Pre-journal array data remains readable/exportable; its individual deletion fails closed instead of rewriting shared bytes.
Undo history and unadded evidence forms are deliberately not archived. Both the replacement warning and archive UI disclose this; cancellation retains them unchanged. Users must add/copy those items before confirming. Do not claim full editor-session recovery.
Confirmed sign-out clears the terminating account's archive, including future records, through the existing explicit privacy boundary. Failed sign-out retains it; another account's archive is unaffected. Ordinary recovery and known-format cleanup preserve unsupported raw records. This distinction preserves the existing logout contract.

Review findings fixed after implementation
1. Normalize the current eligible draft before comparing it with a retained device record; otherwise a single graph could consume two entries solely because of normalization.
2. Capture authority epoch/scope as primitives; an in-place test snapshot must not hide identity changes.
3. Archive before active-slot deletion in the central path; failure must not complete replacement as v106 did.
4. Extend confirmed logout cleanup to the new archive, rather than leaving retention outside the established privacy boundary.
5. Cancel an older Canopy launch when a new category example is requested.
6. At a 320-pixel viewport, body min-width:320px plus a 15-pixel scrollbar produced 15 pixels of horizontal page overflow. Remove the body minimum; rechecked document scroll width = client width = 305 pixels.
7. Replace shared-array archive writes with independent immutable record keys; stale tabs cannot overwrite other entries. Recheck capacity after append and roll back only the failing attempt. Add tests for interleaved appends, capacity races, backup round-trip and account-bound future-data cleanup.
8. Clarify that a reopened/remounted editor has no current calculation in that editor, while reports independently calculate current inputs. This resolves a misleading empty-result message observed alongside a correctly calculated PDF.

Work package 8: measurement contract and pilot
Audit found operational Worker logs and anomaly aggregation, not a consent-aware adoption funnel. Do not repurpose operational telemetry, persist product-D1 events or add a vendor to manufacture adoption evidence.
Proposed event contract, schema studio-adoption-v1:
template_selected / example_selected: emit once per explicit accepted selection; payload category enum, locale enum, format enum, entrypoint enum.
meaningful_edit: first committed graph/input change per local case visit, not keystrokes; payload category, locale, origin own/example.
calculation_succeeded: only a verified fresh calculation; deduplicate by source + input + revision locally; payload category, locale, engine enum, result state enum (no numbers).
workspace_save_verified: exact server receipt only; deduplicate by exact saved version in memory; payload category, locale, origin.
workspace_reopened: authorized verified payload after a separate open; deduplicate by visit; payload category, locale, origin.
report_delivered: renderer/download completion and receipt, distinguish initiated/delivered/history-recorded; deduplicate by renderer/options/exact version locally; payload category, locale, profile enum, language enum, outcome enum.
Ownership: Studio lifecycle/controller emits committed transitions; report controller owns delivery; PO owns event semantics; privacy owner approves consent and retention. Random per-event dedup tokens may be transmitted only after an explicit consent decision; account/email/organization/case/source IDs and fingerprints stay out of adoption payloads. No titles, facts, prompts, amounts, financial results, documents, URLs, reports or private identifiers. Dedup bindings can exist in local memory without being sent. Consent denial/withdrawal suppresses collection; operational failure logs continue under their existing separate contract.
Status: specification complete for review; no adoption collector or consent UI implemented. Approve purpose, lawful consent workflow, retention and aggregator access before connecting the events. Participant work is gated by preservation, hosted and accessibility acceptance.
Activation hypothesis: an own case, meaningfully edited, verified saved, independently reopened and used for a reviewable report. Example browsing/calculation is exploration, not activation. No activation count, success rate, time-to-result or willingness-to-pay is claimed.
Pilot: recruit actual novice and experienced target users across supported locales/access needs. Tasks: select the right template, enter own synthetic/de-identified evidence, calculate, save, leave/reopen, explain freshness/review state, obtain a report, replace/restore work and recover from a failed action. Record unassisted completion, misconceptions, lost work, time-to-result and confidence; obtain consent before recording. Proposed 80% success and 10-minute first-result targets remain hypotheses until baseline and PO agreement.
Defer favorites, dense filtering, personalization, pricing expansion and broad team approval work until observed need and willingness-to-pay evidence.
