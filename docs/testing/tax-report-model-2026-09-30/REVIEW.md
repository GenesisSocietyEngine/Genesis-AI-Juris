## Implementation and review

`app/tax-report-model.ts` consumes only the verified `TaxReportSnapshot` returned by fresh execution. It clones and freezes inputs before awaiting hashing. The semantic fingerprint includes the complete attachment digest, P4A descriptor, artifact context, every protocol/calculation version, normalized request, bindings/required IDs, Rust hashes, missing inputs and full result. It excludes the private full-draft identity: `updatedAt`, protection and history must instead be bound by the outer report if emitted. The returned model contains digest/identity metadata and explicit labelled rows, not the raw semantic evidence body or attachment.

All amounts use the existing integer/string formatter. Rates, months, source confirmation owner/date, manual override, benefit timing/probability and assumptions are presented without financial recomputation. The ROI reason and steady-state nature of simple payback are explicit. The heading is “Current calculation”; implementation/runtime identity belongs in metadata.

Historical FX is a narrow projection of the recognized Rust `web_rates_fx_v1` legacy record. The original SHA-256 is checked, the retained `fx_json` must equal the original top-level FX token exactly, and only five scalar fields are permitted. The exchange-rate token is copied without a Number round trip. Arbitrary originals, converted historical requests, prior source documents and unsupported FX fields are never printed. This establishes retained-byte identity, not authenticity or professional approval of a historical source.

Cross-slice editor review caught a storage-shape mismatch before activation: the actual editor retains raw originals plus complete `tax_imported` responses, whereas the initial projector recognized a bare legacy record only. The projector now recognizes that exact supported envelope as well, and the regression covers the actual full-response storage shape while keeping arbitrary originals private.
