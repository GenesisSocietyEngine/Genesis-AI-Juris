## Amendments to the connected-notes design

The source recheck confirms that `DocumentsSection` currently foregrounds upload, document metadata, current-version download and version history. `SourceCitation` displays bounded exact excerpts. `openAction` focuses known loaded targets but currently reports an unloaded target rather than retrieving it. There is no governed notebook/note table. Legacy `caseFeedback` is not an appropriate shared dossier-note store.

The new screenshots refine the previous design as follows. These are **implementation specifications, not completed features**.

| Current action point | Proposed presentation | Exact destination / required addition | Completion behavior |
|---|---|---|---|
| Start a case note | Create note in Documents & evidence; Blank, Meeting notes or Analysis as lightweight choices | A case-scoped note editor with persistent note ID, title and working text; visible case breadcrumb | Show saved note revision/time only after persistence; preserve text on recoverable failure |
| Add existing material while writing | Prominent Link existing; Upload new remains a separate action | Search authorized same-case documents/versions/anchors; show title, type, version and actual review state; mark already-linked records | Confirm the association receipt and update the linked-source list; duplicate submissions create one relationship |
| Read linked material | Compact row with source title, referenced version and section/page when available; Open source primary, Download secondary | Exact document/version or evidence-anchor target with originating note ID, draft, selection and scroll position retained | Return to the same note; a failed preview leaves secure source download or an exact error/retry path |
| Inspect reuse | Used in, derived from real permitted associations | Exact linked note/assertion locations, with authorization applied to entries and counts | No restricted titles/snippets/counts; unavailable links explain access without selecting another record |
| Remove a contextual relationship | Unlink in the row's contextual menu | The association ID, not the underlying source or evidence acceptance | Confirm removal, preserve the source and all other links; refresh counts from the server |
| Turn analysis into support | Submit sourced assertion as an explicit action | Existing assertion-creation workflow with accepted, non-retired same-case anchor IDs and dossier revision | Result remains awaiting review. Saving a note or checking a box never accepts evidence or makes a case ready |
| Find notes again | Compact case-note list with title/type/author/saved time; meaningful empty state | Existing case navigation; search authorized note metadata/content through a bounded case query | Persistent identity survives rename; navigation resets at organization/case boundaries |

Retain the proposed independent note revision/history so ordinary contextual writing does not automatically stale governed reports. Use existing owner/contributor update authority, active case participation and organization boundaries. Start with **Working material · shared with this case**; private notes and cross-case shared sources are outside the first increment. Linked evidence remains pinned to its reviewed version, with a newer current version shown separately.

The first reading layout should reuse the established `--workspace-*` tokens and shared controls, with a modest title, concise saved/sharing properties, readable narrative and compact linked records. One Save note primary action, secondary Link existing and contextual advanced options are sufficient initially. Do not import a second colour palette or arbitrary property/automation system. Use existing 44px minimum controls and narrow-screen patterns; these are implementation targets until rendered checks pass.

The requested Canopy exercise still needs both sources: **D09 v1** supplies delivery context; **D08 v2, Leadership** supplies staffing confirmation. Keep the Staffing analysis note and link both with their different purposes before explicit assertion review. The reference screenshots do not change that factual distinction.
