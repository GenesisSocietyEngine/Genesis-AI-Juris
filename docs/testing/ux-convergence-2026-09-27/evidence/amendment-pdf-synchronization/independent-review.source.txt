## Recommended test-only correction

Replace the finite `setImmediate` loops around held PDF renders with a **test-owned held-renderer signal plus a bounded real-time timeout**. Keep the production authority implementation unchanged.

1. The renderer double captures the current test's PDF state and notifies a start waiter immediately after appending its held finish callback. Register the waiter before clicking; alternatively, a helper must check the queue before subscribing so it cannot miss a synchronous start.
2. Bind each wait to the expected operation/count. Retain `assert.equal(pdf.finish.length, expectedCount)` after the signal. The overlapping old-preview/new-account case must still require exactly two held callbacks. Do not use an earlier render's notification for a later operation.
3. Race renderer entry against both a real wall-time deadline (for example five seconds) and **premature completion/rejection of that click promise**. Early completion without renderer entry must fail with a useful setup diagnostic, rather than wait until timeout or be treated as success. Clear the timer/listener in `finally`.
4. Only after the held callback is confirmed may the test change `signedIn`, account scope, options or authority epoch; then release that same callback and await the actual parent operation. This preserves the test's intended ordering and all negative side-effect assertions.
5. On failure, invalidate/unmount first, release/drain test-owned held operations and settle their promises before clearing global hook/PDF fixtures. A timed-out asynchronous operation must not resume into the next test's globals. Keep this cleanup bounded; the renderer double can support disposing its own pending work without changing production behavior.

The same file contains six analogous ten-turn queue waits in the preceding receipt test. Applying the same small helper to those held-renderer barriers is a coherent test-only correction; unrelated history polling should not be broadened into this patch.
