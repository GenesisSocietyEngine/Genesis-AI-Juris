## What the user experience now supports

The shell places useful case content earlier, with shared navigation and a shorter header. The principal sections—Overview, Sources, Decision, Review and Reports—give the advisory workflow a clearer structure, while technical metadata is generally secondary. A direct Canopy entry exposes an actual prepared conclusion, its basis and limitations. Empty cases and unavailable reports have actionable explanations. The two existing tax choices now explain their distinction without changing registry IDs or inventing capabilities.

Evidence is more intelligible. Document/version counts are distinguished from graph records. Source links target actual retained material; where governed evidence is required, the UI uses the existing Matter workflow and an exact originating context if one is available. Otherwise it asks the person to choose a case. Studio and Matter are still distinct entities: there is no hidden match by case title or fabricated association.

The decision map supports overview, detail, list and expanded modes. Retained checks preserve the Canopy model's 14 nodes and 13 links, branch labels, inspector selection and keyboard behavior. Changes can mark prior conclusions or receipts as requiring reassessment. The interface does not claim that a fingerprint change automatically performs professional reconsideration.

Saving and returning are substantially better evidenced than at the initial review. Actual local journeys cover authorized save/reload/reopen, guest cancel/sign-in continuation, stopped-network retry, controlled session expiry/recovery and a real two-tab conflict that retains the losing tab's edits. The saved-case loading race that silently replaced the requested Decision tab with Brief was fixed and retested. These observations do not cover every cross-section, organization or hosted session state.

Reporting now has explicit Base, Medium and Full choices with their supported tree behavior, current-versus-earlier receipts and account history for eligible saved Studio versions. The compatibility rule is preserved: Base with tree ON becomes Medium; Medium with tree OFF becomes Base; Full starts with tree ON and remains Full when the tree is switched OFF. Full OFF also omits its coupled explanatory graph text; a separate legacy appendix switch did not exist. A real Base PDF was opened and inspected, and its account receipt survived reload. The receipt records a client-reported download start; it does not prove that a person saved the file, and it is not a governed professional approval. Studio receipt history stores metadata, not the original PDF bytes; current case access is required, and account deletion removes that actor's receipts. It is not a permanent governed archive.

The private-read correction adds a final authority check before returning prepared Matter content, permission projections or private file responses. A user whose identity, membership or role changes during a slow read must not receive the earlier prepared result. Unchanged authorized responses keep their content, status and headers. This security fix is separate from the remaining user-comprehension work.

Preservation is part of the acceptance contract: reference demos remain distinct from editable copies; case-type IDs, retained training rules, source/version lineage and audit history were not replaced to simplify the screens. No destructive migration, title-based entity merge, new AI provider, billing feature or relaxed organization/authentication rule was introduced by these slices. Existing prototype/client-data restrictions remain; explicit AI actions are not permission to send additional material. The later synchronization correction changes a test only. Unrelated outer-workspace/mobile work, local credentials and synthetic databases remain outside these commits. Scoped preservation evidence does not establish that every untested legacy route is correct.
