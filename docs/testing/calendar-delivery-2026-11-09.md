# Calendar subscriptions and recipient reminders — 9 November 2026

The owner selected one-way publication: CaseVant is the source of truth. Scope is either the selected case or firm work without a case. Publishing is opt-in for an authorized editor. Individual calendar accounts are not connected with OAuth.

| User journey | Acceptance evidence |
| --- | --- |
| Subscribe, reschedule, withdraw, rotate and stop | Real D1 route tests read a feed without a browser session, retain the same UID through date changes and withdrawal, receive a cancellation for an undated/removed item and invalidate replaced or revoked links. Reinstating membership does not resurrect an old link. Firm work and separate cases are isolated. |
| Read in calendar clients | RFC 5545 CRLF, Unicode line folding at 75 octets, text escaping, exclusive all-day end and UTC instants across a repeated clock hour are tested. Only titles and dates are published. Withdrawals remain visible for 90 days. Refresh and removal of downloaded entries are controlled by the calendar client. |
| Schedule and dismiss | Active organization membership plus case participation where applicable are required. A reviewed save for up to 20 recipients is atomic; stale work or an ineligible recipient rejects the batch. A recipient sees their own entries and dismisses independently. The scheduler can also cancel one recipient’s unsent reminder without changing another’s. Shared work-item reminders are unchanged. Personal reminders use a fixed local time and named zone; DST gaps are rejected and repeated times require a choice. |
| Deliver without the app open | A repository-owned scheduled workflow calls a dedicated endpoint using a signed GitHub identity restricted to this repository, workflow and main branch. It sends no case title, work title or notes in the email. D1 tests use a synthetic provider for duplicate workers, lost responses, retry, accepted/delivered, permanent rejection, expiry, completion and revoked membership. Clock-driven in-app reminders do not claim email delivery. |
| Preserve existing work and navigation | Additive migration 0034 checks every preceding populated table before and after the upgrade. The real English browser UI retained the selected case from Calendar to Reminders, showed the saved reminder, and confirmed personal dismissal. A Russian case calendar in a 390px frame showed no page or form overflow; visible commands measured 36px on desktop and 44px on narrow screens. |
| Recovery and release boundary | Link versions prevent stale changes; reminder operations and provider requests have independent duplicate protection. Uncertain emails stop retrying before the provider's 24-hour duplicate window. Provider acceptance is not a mailbox receipt. Removing access prevents future reads/sends but cannot recall downloaded calendars or already transmitted email. A live Outlook/Google refresh and delivery to a real person's mailbox were not exercised. |

The signed dispatcher runs approximately every ten minutes; GitHub may delay a scheduled run. Failed or uncertain delivery remains visible to the sender. A manual run defaults to inspecting the queue without sending. Email requires the existing transactional sender and a trusted HTTPS public origin.
