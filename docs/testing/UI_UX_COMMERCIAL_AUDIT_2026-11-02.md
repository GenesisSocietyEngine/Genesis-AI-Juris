## 2. What should remain

CaseVant already has useful foundations: a five-section workspace; separate examples and working copies; category/source identities; missing-original disclosures; evidence-safe bulk operations; saved identity/version contracts; conflict/context fences; historical recovery; scenario comparison; and complete report options. The existing materials result/action separation, consistent entry columns, graph zoom/palette and actionable review routing should be verified and refined rather than reimplemented.

The product's plausible differentiator is a decision package connecting mandate, precise support, alternatives, uncertainty, owner and next action. The first commercial hypothesis is a lawyer/consultant in a small professional team preparing a reviewable advisory or early-dispute memorandum. This segment and willingness to pay remain hypotheses. Canopy supplies the bounded fictional demonstration; GreenFire tests a more demanding chronology/gap journey. Nine categories remain available without implying nine domain-validated solutions.

### Fresh security interpretation

The [reviewed minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249) lists versions below11.0.1 and describes glob-pattern amplification. The audited lock contains3.1.5 and10.2.5. This requires careful API/exposure analysis: do not assume every listed older API shares the demonstrated code path, and do not treat that uncertainty as an audit waiver. npm suggests major downgrades of ESLint/Next lint configuration; those are not an accepted fix. Do not force an11.x override into a3.x function API. A compatible supported update or reproducible scoped backport needs direct consumer/glob/negation/platform tests plus the existing gates. No dependency was amended in this audit. Production-only0does not close this build/release issue.

## 5. Proposed UX system

Use one stable case header: title, category, workspace/account scope and truthful save state; one primary action for the current task. Keep secondary actions in a labelled menu. Reserve red for error/destructive states, amber for unresolved attention, teal for primary action and blue for navigation. Never convey evidence acceptance or approval through colour alone. Apply existing design tokens to a small shared set of buttons, fields, status notices, dialogs and empty states before considering a broad theme change.

Keep Overview, Sources & evidence, Decision, Review and Reports. Brief & structure remains preparatory. Default a new user into a clear task and explain its next step; preserve expert navigation and historic URLs. Graph and list should reference the same selected node and numeric prefix, with no reordered saved identifiers. Map zoom, drag/drop, floating palette and inspector must not obscure selections or create a second competing save workflow.

The preferred evidence interaction is finding → exact version/passage → linked node → return to the same finding/filter/scroll. Every object distinguishes original supplied file, illustrative reference, working statement, URL-only source and missing original. Human review is separately recorded. Bulk reattachment previews its destination and count, retains bytes and conflict carriers, and leaves deleted-node evidence discoverable. Existing working-copy and authority fences remain mandatory.

Accessibility target: WCAG2.2AA verification of the changed journeys, including visible/unobscured focus, keyboard operation, labels, error feedback, contrast and reflow. Product touch-target goal is44CSSpx; WCAG2.2's AA minimum target criterion is24CSSpx with stated exceptions, not a blanket44px requirement. Inspect actual measurements at390px, the800/801px breakpoint, short height,200%zoom, EN/RU and long titles. Do not infer conformance from CSS declarations. [Normative reference](https://www.w3.org/TR/WCAG22/).

## 6. Commercial readiness decision

| Gate | Current assessment | Evidence required to change it |
| --- | --- | --- |
| Technical deployed prototype | Established for the scoped v163 web release | Maintain current-source security/runtime regression gates |
| Supervised fictional demonstration | Conditional; fresh completion packet missing | One complete Canopy journey plus GreenFire gap handling, exact saves/reopens and actual portable/report/material outputs, with user-visible limits |
| Customer-data pilot | Hold | Operator-approved permitted-data/processing/access/retention/support decision; tenant/context isolation acceptance; qualified review |
| Paid repeatable product | Not established | Consented target-user completion and repeated use, buyer and budget evidence, support ownership and evaluated output quality |
| Native readiness | Current-main CI green within recorded scope | Inspect retained raw artifacts and separately address historical cold-first/padding acceptance before broader claims |

A proposed north-star measure is completed, saved/reopened, source-checked decision packages per active eligible workspace, with reviewer disposition and an inspected export. Initially measure it manually in consented synthetic studies. Do not add analytics or transmit case text to measure it. The prior30-second/80%retrieval proposal remains a hypothesis: run at least five consenting evaluators, report median/range, correctness and assistance, and show raw small-sample results rather than a statistically strong claim. Compare existing practice with CaseVant on the same tasks; do not borrow competitors' ROI percentages.

Proposed positioning for testing: help a professional turn a bounded evidence set into a reviewable decision memorandum with visible uncertainty and next actions. Validate this against real buyer language before changing the homepage. Pricing interviews may test who pays, what result matters and preferred unit; no price change, payment integration, outreach or recruitment is authorized by this audit. Enterprise SSO, broad connectors, autonomous filing, mobile expansion and agent marketplaces are later demand-led decisions.
